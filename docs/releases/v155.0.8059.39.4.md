## JithuBrowser 155.0.8059.39.4 (Linux x86_64 + Windows x64)

A privacy-focused browser built on official Chromium **155.0.8059.39**. Chrome-only websites keep working; pages just can't watch what you do.

### What's new in .4
- **Background tabs no longer give themselves away.** A hidden, minimised or covered tab used to run its timers at about 1 per second and stop `requestAnimationFrame`, which any page could measure (in our test: 4 timer ticks in 4 seconds instead of about 80). Hidden tabs now run like visible ones. **Cost:** background tabs use more CPU/battery; in one synthetic test a hidden tab running a heavy animation used about 9 percentage points more of a CPU core. Turn it off with `--disable-features=JithuBrowserKeepHiddenTabsActive`.
- **Own enterprise-policy location.** A Chromium on the same machine can no longer push its enterprise policies into JithuBrowser. Linux: `/etc/jithubrowser/policies`. Windows: `Software\Policies\JithuBrowser`.

### What it hides from websites
Tab switching and minimising, window focus, browser fullscreen and window geometry, background-tab timer and animation-frame rates, `history.length`, `navigator.webdriver`, exact version/OS/device in the User-Agent and Client Hints (looks like stock Google Chrome), keyboard layout, typing-rhythm timestamps, which browser shortcuts you press, and hidden-tab tells in `screen.avail*`, `screen.isExtended`, mouse `screenX/Y`, Wake Lock and `navigator.vibrate()`. Every English menu, the About page and the installer text say "JithuBrowser". Remaining limits are in `docs/DESIGN.md` (for example `performance.now()` inside a key handler is not jittered, and the Navigation API still shows true history depth).

### What was tested (and how)
- **Privacy suite, 20 tests.** Linux build: **20/20 pass** (stock Chrome 155: 16 fail). Windows build under **Wine 11**: **20/20 pass** (stock Windows Chrome 155 under the same Wine: 15 fail). The few tests stock Chrome also passes cannot tell the difference in a virtual-display test setup.
- **Real installs, on the final files.** `.deb`: `apt` install, run, clean removal on Ubuntu 22.04. `.rpm`: `dnf` install on **Rocky Linux 9.8**, ran, `rpm -V` clean, clean removal. `.tar.xz` launches.
- **Chrome Web Store.** A real extension (Dark Reader) was force-installed from the Web Store through enterprise policy (the same download/verify/install code as the "Add to Chrome" button) and its service worker ran. Unpacked Manifest V3 extensions behave identically to stock Chrome.
- **DRM.** The Widevine module downloads on first run and, after a restart, the browser can create a Widevine key session (H.264/AAC capabilities reported).
- **Real websites.** 20 sites: **18/20 load identically to stock Chrome, 0 regressions, no "unsupported browser" notices** (WhatsApp Web and Microsoft Teams loaded blank in both browsers on this network).
- **Policy isolation.** A policy file in `/etc/chromium/policies` is ignored; one in `/etc/jithubrowser/policies` is applied.

### Not tested / be aware
- **Windows has not been run on real Windows**, only under Wine. It is cross-compiled on Linux, **not code-signed** (SmartScreen will warn: "More info", then "Run anyway"), WebGPU uses Windows' own shader compiler, and it still shares some system registration IDs with Chromium, so do not install it next to Chromium on the same PC.
- A real `pacman`/Arch package build, and `.rpm` on Fedora/openSUSE (only Rocky 9 was tried).
- The setuid sandbox with real root (tests ran in a rootless sandbox with `--no-sandbox`).
- Clicking "Add to Chrome" in the Web Store page itself, and playing a paid DRM stream end to end (only session creation was tested).
- Sites' functionality beyond loading and the "unsupported browser" check.
