## JithuBrowser 155.0.8059.39.5 (Linux x86_64 + Windows x64)

A privacy-focused browser built on official Chromium **155.0.8059.39**. Chrome-only websites keep working; pages just can't watch what you do. The browser itself is the same as 155.0.8059.39.4; this release fixes packaging problems found by testing on more Linux distributions.

### What's fixed in .5
- **The `.rpm` now installs on openSUSE.** In .4 it listed Fedora-style package names (for example `at-spi2-atk`) that openSUSE does not have, so `zypper` refused it. It now depends on the shared libraries the browser actually loads, which every RPM distro can provide. Fedora and Rocky still work.
- **The Linux `.tar.xz` no longer records the build machine's user and group IDs** (all files are `root:root`).

### What it hides from websites
Tab switching and minimising, window focus, browser fullscreen and window geometry, background-tab timer and animation-frame rates (hidden tabs keep running like visible ones, at some extra CPU/battery cost; `--disable-features=JithuBrowserKeepHiddenTabsActive` turns it off), `history.length`, `navigator.webdriver`, exact version/OS/device in the User-Agent and Client Hints, keyboard layout, typing-rhythm timestamps, which browser shortcuts you press, hidden-tab tells in `screen.avail*`, `screen.isExtended`, mouse `screenX/Y`, Wake Lock and `navigator.vibrate()`. Own profile folder and own enterprise-policy location, separate from Chromium's. Remaining limits are in `docs/DESIGN.md`.

### What was tested (and how)
- **Privacy suite, 20 tests.** Linux: **20/20 pass** (stock Chrome 155: 16 fail). Windows build under **Wine 11**: **20/20 pass** (stock Windows Chrome: 15 fail).
- **Real installs on the final files / recipe**, each: install, run, `--version`, plain-Chrome user agent, no missing libraries, clean removal.
  - `.deb`: **Ubuntu 22.04** with `apt`.
  - `.rpm`: **Fedora 44** and **Rocky Linux 9.8** with `dnf`; **openSUSE Tumbleweed**: dependencies resolve with `zypper` and the browser runs on openSUSE's own libraries (the install was done with `rpm --nodeps --noscripts` for dependency packages because the unprivileged test sandbox cannot run their user-creation scripts).
  - **Arch Linux**: the `PKGBUILD` was built with `makepkg` (checksum verified against the release tarball) and installed with `pacman -U`; `pacman -Qk` reports 0 missing files.
- **Chrome Web Store.** A real extension (Dark Reader) was force-installed from the Web Store through enterprise policy and ran; unpacked Manifest V3 extensions behave like stock Chrome.
- **DRM.** The Widevine module downloads on first run and, after a restart, a Widevine key session can be created.
- **Real websites.** 20 sites: 18 load identically to stock Chrome, 0 regressions, no "unsupported browser" notices.
- The binaries contain no build-machine user name, home path or e-mail address.

### Not tested / be aware
- **Windows has not been run on real Windows**, only under Wine. It is cross-compiled on Linux, **not code-signed** (SmartScreen will warn: "More info", then "Run anyway"), WebGPU uses Windows' own shader compiler, and it shares some system registration IDs with Chromium: do not install it next to Chromium on the same PC.
- The setuid sandbox with real root (tests ran in a rootless sandbox with `--no-sandbox`).
- Clicking "Add to Chrome" in the Web Store page itself, and playing a paid DRM stream end to end (only session creation was tested).
- Websites' functionality beyond loading and the "unsupported browser" check.
