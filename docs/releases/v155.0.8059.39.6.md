## JithuBrowser 155.0.8059.39.6 (Linux x86_64 + Windows x64)

A privacy-focused browser built on official Chromium **155.0.8059.39**. Chrome-only websites keep working; pages just can't watch what you do.

### What's new in .6: the last two known privacy gaps are closed
- **Typing rhythm can no longer be read with `performance.now()`.** Until now only `event.timeStamp` was blurred, so a page timing keystrokes in its own handler still saw your true rhythm (on stock Chrome it is accurate to under 1 ms). Key-down and key-up events now reach the page after a random delay of up to 20 ms, in order, and a click can never overtake a keystroke. **Cost:** about 10 ms of extra latency on average for each typed character. `--disable-features=JithuBrowserKeystrokeJitter` turns it off.
- **The Navigation API no longer reveals how many pages you visited.** `navigation.entries()` shows only the current entry and the one before it (like `history.length`).

### What it hides from websites
Tab switching and minimising, window focus, browser fullscreen and window geometry, background-tab timer and animation-frame rates (hidden tabs keep running like visible ones, at some extra CPU/battery cost; `--disable-features=JithuBrowserKeepHiddenTabsActive` turns it off), `history.length` and the Navigation API's history depth, `navigator.webdriver`, exact version/OS/device in the User-Agent and Client Hints, keyboard layout, typing rhythm (timestamps and `performance.now()`), which browser shortcuts you press, and hidden-tab tells in `screen.avail*`, `screen.isExtended`, mouse `screenX/Y`, Wake Lock and `navigator.vibrate()`. Own profile folder and enterprise-policy location, separate from Chromium's. Remaining limits are in `docs/DESIGN.md`.

### What was tested (and how)
- **Privacy suite, 22 tests.** Linux: **22/22 pass** (stock Chrome 155: 18 fail). Windows build under **Wine 11**: **22/22 pass** (stock Windows Chrome: 17 fail). A separate stress test confirms typing 400 characters repeatedly with the delay on keeps every character in order, and a click right after typing sees all of them.
- **Sandbox.** Started *without* `--no-sandbox` as a normal user with no privileges, every renderer process runs with a seccomp filter (`Seccomp: 2`, `NoNewPrivs: 1`) in its own user namespace, i.e. Chromium's real sandbox is engaged. (The setuid-helper fallback used where user namespaces are disabled could not be tested without real root.)
- **Chrome Web Store.** Opened the real Web Store page, clicked **"Add to Chrome"**, confirmed the native dialog: Dark Reader installed and its service worker ran. Installing the same extension through enterprise policy also works.
- **DRM.** The Widevine module downloads on first run and, after a restart, a Widevine-encrypted test stream (Shaka Player's "Angel One", license from Google's test server) **plays end to end**: license acquired, content decrypted and decoded, 208 frames in 8 s. A paid streaming service uses the same pipeline but was not tested.
- **Real installs** (on the published .5 packages, same packaging code in .6): `.deb` on Ubuntu 22.04; `.rpm` on Fedora 44, Rocky Linux 9.8 and openSUSE Tumbleweed (zypper resolves; run on openSUSE's own libraries); Arch Linux via `git clone` + `makepkg` + `pacman -U`.
- **Extensions** (unpacked MV3) behave identically to stock Chrome. **Real websites:** 20 sites, 18 load identically to stock Chrome, 0 regressions, no "unsupported browser" notices.

### Not tested / be aware
- **Windows has not been run on real Windows**, only under Wine. It is cross-compiled on Linux, **not code-signed** (SmartScreen will warn: "More info", then "Run anyway"), WebGPU uses Windows' own shader compiler, and it shares some system registration IDs with Chromium: do not install it next to Chromium on the same PC.
- The setuid sandbox helper with real root (the default user-namespace sandbox was tested, see above).
- Playback from a paid streaming service, and websites' functionality beyond loading and the "unsupported browser" check.
