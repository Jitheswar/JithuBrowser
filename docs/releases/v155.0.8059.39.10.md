## JithuBrowser 155.0.10059.39.10 (Linux x86_64 + Windows x64)

A privacy-focused browser built on official Chromium **155.0.10059.39**. Chrome-only websites keep working; pages just can't watch what you do.

### What's new in .10
- **Settings page** at `chrome://jithubrowser-settings` (main menu → **JithuBrowser settings**): see, add and remove the sites where protections are off, and a checkbox to **hide the two JithuBrowser entries in the main menu** (the page stays reachable by its address; `--jithubrowser-hide-menu-items` does the same).
- **Windows: Install update.** The update bar's button now downloads the new installer from the release, checks its SHA-256 against the release's `SHA256SUMS`, and starts it; the setup window shows progress. On Linux the bar still opens the download page (installing there needs administrator rights). The download-and-checksum steps were tested end to end on Linux; the launch step was not run on Windows.
- **More fingerprint protection:** WebGL `readPixels` and audio `AnalyserNode` output are now perturbed too (canvas, WebGL names and offline audio were in .9).
- **Quiet mode (opt-in):** start with `--jithubrowser-quiet-google` to stop Chromium's own background requests to Google: component updates, push messaging, the account-cookie check and the time check. Costs: Widevine and certificate-revocation lists stop updating, and no web push. New-tab-page / search warmup requests and the spellcheck dictionary download are not covered.
- Privacy suite grew to 35 tests.

### What it hides from websites
Tab switching and minimising, window focus, canvas/WebGL/audio fingerprints (partly), browser fullscreen and window geometry, background-tab clocks and muted-video pausing (hidden tabs keep running like visible ones, at some extra CPU/battery cost; `--disable-features=JithuBrowserKeepHiddenTabsActive` turns it off), `history.length` and the Navigation API's history depth, `navigator.webdriver`, exact version/OS/device in the User-Agent and Client Hints, keyboard layout, typing rhythm (timestamps and `performance.now()`), which browser shortcuts you press, what you search for with Find in page, and hidden-tab tells in `screen.avail*`, `screen.isExtended`, mouse `screenX/Y`, Wake Lock and `navigator.vibrate()`. Own profile folder and enterprise-policy location, separate from Chromium's. Remaining limits are in `docs/DESIGN.md`.

### What was tested (and how)
- **Privacy suite, 35 tests.** Linux: **35/35 pass** (stock Chrome 155: 31 fail). Windows build under **Wine 11**: **34 pass, 1 skipped** (the WebGL `readPixels` test needs WebGL, which Wine does not provide, so that protection is unverified on Windows; stock Windows Chrome: 28 fail).
- **Sandbox**, default user-namespace sandbox as a normal user without `--no-sandbox`: renderers run with seccomp and `NoNewPrivs` (checked in .6; code unchanged in .10).
- **Chrome Web Store** "Add to Chrome" click installs an extension; **Widevine** DRM plays an encrypted stream end to end (both checked in .6).
- **Real installs** (previous releases' packages; packaging code is unchanged): Ubuntu 22.04 `.deb`; Fedora 44, Rocky 9.10, openSUSE Tumbleweed `.rpm`; Arch `makepkg` + `pacman -U`.
- **Real websites:** 20 sites, 18 load identically to stock Chrome, 0 regressions. **Extensions** behave identically to stock Chrome.

### Not tested / be aware
- **Windows has not been run on real Windows**, only under Wine. It is cross-compiled on Linux, **not code-signed** (SmartScreen will warn: "More info", then "Run anyway"), WebGPU uses Windows' own shader compiler, and it shares some system registration IDs with Chromium: do not install it next to Chromium on the same PC.
- The setuid sandbox helper with real root, and playback from a paid streaming service.
- **The Windows setup window and its installer were not run on real Windows.** Under Wine the window renders and runs the installer, but Chromium's installer itself cannot finish under Wine (with or without the window), so a real install is unverified. The update bar and the settings page were checked on Linux only; Windows auto-install (the final launch step) was never run.
- Stock Chromium's own connections to Google services (component updater and similar) are unchanged by JithuBrowser.
