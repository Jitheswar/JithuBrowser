## JithuBrowser 155.0.9059.39.9 (Linux x86_64 + Windows x64)

A privacy-focused browser built on official Chromium **155.0.9059.39**. Chrome-only websites keep working; pages just can't watch what you do.

### What's new in .9
- **Fingerprint protection.** Canvas readbacks (`getImageData`, `toDataURL`, `toBlob`) differ by at most 1 in about a quarter of the pixels, WebGL reports a generic GPU name instead of yours, and offline audio renders are perturbed by about one part in ten million, so those values no longer identify your machine. Turn each off with `--disable-features=JithuBrowserFarbleCanvas`, `...FarbleWebGL` or `...FarbleAudio`. **Not covered:** WebGL `readPixels`, `AnalyserNode`, font probing.
- **Per-site switch.** App menu → **JithuBrowser protections for this site** turns the in-page protections off for a site that breaks (and its subdomains); `--jithubrowser-unprotected-sites=a.com,b.com` does the same from the command line. User-Agent / Client Hints, browser shortcuts and silent fullscreen stay on.
- **Update notification.** 30 seconds after start the browser asks GitHub (one plain HTTPS request, no cookies) whether a newer release exists and shows a bar with **Open download page**. It never installs anything by itself. Turn it off with `--disable-features=JithuBrowserUpdateCheck`.
- **Windows installer now shows a setup window** with an animated progress display and a clear "installed" or "failed" screen. Before, it ran silently, so double-clicking it looked like nothing happened. It runs Chromium's own installer unchanged inside it; `--silent` hides the window. The window was tested under Wine only.
- Privacy suite grew to 32 tests (canvas, canvas blob, audio, per-site switch).
- Fixed a packaging mistake that was introduced after .8 on `main` (a patch lost two build-file entries); not present in any published release.

### What it hides from websites
Tab switching and minimising, window focus, canvas/WebGL/audio fingerprints (partly), browser fullscreen and window geometry, background-tab clocks and muted-video pausing (hidden tabs keep running like visible ones, at some extra CPU/battery cost; `--disable-features=JithuBrowserKeepHiddenTabsActive` turns it off), `history.length` and the Navigation API's history depth, `navigator.webdriver`, exact version/OS/device in the User-Agent and Client Hints, keyboard layout, typing rhythm (timestamps and `performance.now()`), which browser shortcuts you press, what you search for with Find in page, and hidden-tab tells in `screen.avail*`, `screen.isExtended`, mouse `screenX/Y`, Wake Lock and `navigator.vibrate()`. Own profile folder and enterprise-policy location, separate from Chromium's. Remaining limits are in `docs/DESIGN.md`.

### What was tested (and how)
- **Privacy suite, 32 tests.** Linux: **32/32 pass** (stock Chrome 155: 28 fail). Windows build under **Wine 11**: **32/32 pass** (stock Windows Chrome: 27 fail).
- **Sandbox**, default user-namespace sandbox as a normal user without `--no-sandbox`: renderers run with seccomp and `NoNewPrivs` (checked in .6; code unchanged in .9).
- **Chrome Web Store** "Add to Chrome" click installs an extension; **Widevine** DRM plays an encrypted stream end to end (both checked in .6).
- **Real installs** (previous releases' packages; packaging code is unchanged): Ubuntu 22.04 `.deb`; Fedora 44, Rocky 9.9, openSUSE Tumbleweed `.rpm`; Arch `makepkg` + `pacman -U`.
- **Real websites:** 20 sites, 18 load identically to stock Chrome, 0 regressions. **Extensions** behave identically to stock Chrome.

### Not tested / be aware
- **Windows has not been run on real Windows**, only under Wine. It is cross-compiled on Linux, **not code-signed** (SmartScreen will warn: "More info", then "Run anyway"), WebGPU uses Windows' own shader compiler, and it shares some system registration IDs with Chromium: do not install it next to Chromium on the same PC.
- The setuid sandbox helper with real root, and playback from a paid streaming service.
- **The Windows setup window and its installer were not run on real Windows.** Under Wine the window renders and runs the installer, but Chromium's installer itself cannot finish under Wine (with or without the window), so a real install is unverified. The update bar was checked on Linux only.
- Stock Chromium's own connections to Google services (component updater and similar) are unchanged by JithuBrowser.
