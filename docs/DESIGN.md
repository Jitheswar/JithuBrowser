# Design notes and limits

* Patches are native (Blink/Chromium C++), not injected JavaScript, so they behave the same in iframes and workers and cannot be seen via `Function.prototype.toString`.
* Every protection is a base::Feature, enabled by default, individually switchable.
* Uniform beats random: the UA, hints, keyboard map and window geometry are the same for everyone, so JithuBrowser users blend together instead of becoming unique.

## Known limits (from an independent multi-agent audit of the patches)

These are not hidden today; the first few are the ones a determined hostile page can still use.

* **A page can still see that a modifier key (Control/Alt/Shift) went down**, but not which shortcut it belonged to: measured with real key presses, the page sees only `Control`, not the `f`/`t`/`l` that follows, and holding a shortcut produces no auto-repeat events. Hiding the modifier itself would break Ctrl+click and games.
* **Other APIs that only work while visible/focused** (auto Picture-in-Picture, Compute Pressure, WebAuthn, pointer lock, gamepad, sensors, lazy-loaded iframes) may still behave differently when the tab is hidden or unfocused; muted-video pausing, timers and animation frames were measured and no longer differ.
* **`history.length` is clamped to 2**, which can confuse sites that count entries (some "return to start" and pushState-counting code).
* Installed web-app windows (`TYPE_APP`) do not get shortcut reservation (upstream gives apps all keys).

**Fingerprint farbling** (`JithuBrowserFarbleCanvas`, `JithuBrowserFarbleWebGL`, `JithuBrowserFarbleAudio`): canvas readbacks (`getImageData`, `toDataURL`, `toBlob`) differ by at most 1 in about a quarter of the pixels (the pattern is random per renderer process and never stored); images of 64 pixels or fewer stay exact so feature detection works. WebGL's unmasked vendor and renderer strings report a generic ANGLE/SwiftShader value instead of your GPU. Offline audio renders are perturbed by about one part in ten million. WebGL `readPixels` (opaque pixels only) and `AnalyserNode` output (float and byte) are perturbed too. **Not covered:** font probing (restricting fonts would break non-Latin text), and the many other ways to fingerprint (screen, timing, hardware concurrency). A determined tracker that averages many readbacks within one process can still estimate the noise.

**Per-site switch** (`JithuBrowserSiteSettings`): the list of sites with protections off lives in the profile (`jithubrowser.unprotected_sites`) and can be edited on `chrome://jithubrowser-settings` (also reachable from the main menu, which can be hidden with the checkbox there or `--jithubrowser-hide-menu-items`) or extended with `--jithubrowser-unprotected-sites=`. The browser tells the tab's renderer whether protections apply when the top-level page navigates. The switch is process-wide inside a renderer: tabs of the same site share it, and if two different sites end up in one renderer process (low-memory process sharing) they share the last setting. It covers everything evaluated in the renderer. It does **not** cover the User-Agent / Client Hints, browser shortcut reservation or silent fullscreen, which run in the browser process.

**Update check** (`JithuBrowserUpdateCheck`): one HTTPS request to `api.github.com` 30 seconds after start (skipped when automation is attached) shows an infobar when a newer release tag exists. On Windows the bar's **Install update** button then downloads the installer from the release, verifies its SHA-256 against the release's `SHA256SUMS` (a download-integrity check only: both files come from the same release, so it does not protect against a compromised release) and starts it. On Linux the bar opens the download page. Nothing is downloaded without that click. This is the only network request JithuBrowser adds; stock Chromium's own requests to Google services are unchanged unless you start with `--jithubrowser-quiet-google`.

**Quiet mode** (`--jithubrowser-quiet-google`, opt-in): stops the component updater's requests (`update.googleapis.com` and the `gvt1.com` downloads), the push-messaging client (`android.clients.google.com`), the Gaia account-cookie check (`accounts.google.com/ListAccounts`) and the network-time check (`clients2.google.com/time`). Checked with a network log (no request to those hosts in 45 seconds). Costs: Widevine DRM and certificate-revocation lists stop updating, and websites cannot send push notifications. Still happening in quiet mode: the new-tab page and default-search-engine warmup requests to `www.google.com` and its font, the spellcheck dictionary download, and Safe Browsing if enabled.

**Switching tabs no longer tells a fullscreen page that you left** (`JithuBrowserSilentTabFullscreenExit`): when a page that went fullscreen at its own request (a video player, an exam page) is switched away from, the window leaves fullscreen as usual but the page is not told (no `fullscreenchange`, `document.fullscreenElement` stays set); fullscreen is restored when you return to the tab. Pressing Esc, F11 or the page's own exit still ends fullscreen and the page sees that, because that is what you asked for. If the browser cannot restore fullscreen, it tells the page the truth instead.

**Find in page no longer reports your search to the page** (`JithuBrowserPrivateFindInPage`): pages can plant hidden "canary" text in `hidden=until-found` blocks or closed `<details>` and learn what you searched for from the `beforematch`/`toggle` events a match triggers (stock Chrome does this). Find now skips collapsed content, so it will not find text inside closed accordions until you open them.

**Typing rhythm and history depth are now closed too** (`JithuBrowserKeystrokeJitter`, `JithuBrowserHideHistoryLength`): key-down and key-up events reach the page after a random delay of up to 20 ms (order is preserved, and a click can never overtake a keystroke), so timing measured with `performance.now()` inside a key handler is blurred as well as `event.timeStamp`; the cost is about 10 ms of extra latency on average for each typed character. The Navigation API now shows at most the current entry and the one before it, like `history.length`; entries beyond that cannot be reached with `navigation.traverseTo()`.

**Background-tab throttling is now closed** (feature `JithuBrowserKeepHiddenTabsActive`): hidden, minimised and occluded tabs keep painting and are not throttled, like a tab that is being screen-captured, so timers and `requestAnimationFrame` run at the same rate as in a visible tab. The price is some extra CPU/battery for background tabs; in one synthetic test a hidden tab running a heavy animation used about 9 percentage points more of a CPU core. Turn it off with `--disable-features=JithuBrowserKeepHiddenTabsActive` if you have many busy background tabs.

Fixed during the audit: `Document::hidden()` now stays truthful for Blink's own scheduling/animation code and only the JavaScript-visible `document.hidden`/`visibilityState` are spoofed; browser-fullscreen media queries are computed on the main thread; shortcut reservation no longer breaks Escape, fullscreen pages or Linux text-editing hotkeys; Wake Lock, `navigator.vibrate()`, `screen.avail*`, `screen.isExtended` and mouse `screenX/Y` no longer leak the same state.
